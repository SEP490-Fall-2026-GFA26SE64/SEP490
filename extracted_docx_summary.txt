Main proposal content (including result and product)    a) Context: Corporate Learning & Development (L&D) and executive education currently rely on rigid Learning Management Systems (LMS). These platforms push static, one-size-fits-all course structures to employees regardless of their existing skills, learning pace, or specific competency gaps. This approach leads to low engagement, wasted training hours, and an inability to align learning outcomes with actual business requirements. The core software engineering and data science gap lies in the absence of a dynamic recommendation system that maps the relationships between human competencies, organizational roles, and learning materials. This project addresses this gap by engineering an Adaptive Learning Platform driven by a Knowledge Graph and Knowledge Tracing methodology. The system evaluates an individual's current competency profile, identifies specific capability gaps compared to target role requirements, and utilizes a graph-traversal recommendation algorithm to generate a highly personalized, dynamic learning pathway. The five specific gaps this project addresses are: - Static Pathways:  Traditional LMS cannot adapt learning routes based on real-time user performance. - Disconnect between Assessment and Learning:  Competency evaluations and training content live in separate, disconnected systems. - Lack of Semantic Mapping:  Standard relational databases struggle to map the complex, multi-layered relationships between macro-skills, micro-skills, roles, and course modules. - Inefficient Training:  Employees waste time studying concepts they have already mastered because the system cannot identify granular knowledge gaps. - No Predictive Upskilling:  Organizations cannot forecast which training modules will yield the highest ROI for transitioning an employee to a new role. b) Proposed Solutions: Adapt-Learn-Graph connects competency assessment, role requirements, and learning modules in a subscription-based, multi-organization web platform. It serves six actors: Guest, Platform Administrator, System Administrator, L&D Manager, Expert, and Employee. The proposed solution combines three architectural pillars: - Competency Intelligence Engine:  Uses baseline and module assessment evidence to estimate employee competencies and identify gaps against a target role. RIASEC interests support AI-assisted role guidance, while skill mastery remains grounded in assessment evidence. - Knowledge Graph Core:  Represents occupations, target roles, competencies, micro-skills, prerequisites, and learning modules in Neo4j. Explicit relationships connect role requirements to suitable learning content, including modules that teach multiple skills and skills covered by multiple modules. - Adaptive Recommendation Algorithm:  Recommends modules based on skill gaps, prerequisites, and learning coverage. An Expert reviews the initial pathway; subsequent assessment results update mastery estimates through knowledge tracing and automatically recalculate the remaining pathway. Self-service registration, subscription payment, and automatic workspace provisioning provide each organization with private data and learning content. Role configuration and content approval workflows support organizational oversight. Employee and department dashboards combine competency gaps, assessment outcomes, learning progress, and training ROI calculated from recorded costs and monetary benefits. Technology stack: - Backend Core:  Java (Spring Boot) for business APIs and backend services. - Database Layer:  PostgreSQL for organizations, registration state, subscription plans and purchased plan versions, payment orders, workspace status, employee-seat entitlements, user memberships, departments, employee department assignments, occupation-to-department links, training cost and benefit records, workflows, learning module and content metadata, assessments, and progress; Neo4j for organization-scoped competency relationships and graph traversal. - File Storage:  MinIO for private learning content and uploaded files, with organization-scoped access controlled by the backend. - Recommendation Engine:  Custom graph traversal and knowledge-tracing logic, compared with a Content-Based Filtering baseline implemented against the same dataset. - Frontend:  React with D3.js or vis.js for competency and pathway visualization. - Payment Integration:  payOS for subscription checkout, payment-status queries, and signature-verified webhooks. - Email Notifications:  SMTP via Gmail for account verification and email notifications. - Local LLM:  A locally hosted language model, accessed through an internal inference API, for AI-assisted target role guidance. - DevOps:  On-premises deployment with Docker Compose, Nginx for web serving and reverse proxying, and GitHub Actions for CI/CD. c) Functional Requirements: - Guest Register an organization:  The Guest shall submit organization and contact details, create an administrator account, verify the account email, and resume an incomplete registration. Employees can view AI-generated explanations directly and choose a published target role; interest scores do not establish skill mastery. Research Problem / Research Question Static recommendation systems (like Collaborative Filtering) suffer from the "cold start" problem and lack semantic understanding of prerequisite skill dependencies. Using a Knowledge Graph can solve this, but query performance and recommendation relevance must be empirically validated in a learning context. - RQ1:  How does the Recommendation Relevance (Hit Rate@5) of the Graph-Traversal algorithm compare to a baseline Content-Based Filtering approach for matching learning modules to skill gaps? - RQ2:  What is the query latency of deep pathfinding operations in Neo4j (e.g., 3-hop to 5-hop depth) as the number of nodes/edges in the competency ontology scales from 1,000 to 10,000? - RQ3:  Does dynamic pathway recalculation (Knowledge Tracing) result in a mathematically shorter distance to the Target Role profile compared to static predefined pathways? b. Research Objectives - Implement and compare a Graph-based recommendation engine against a traditional baseline algorithm. - Benchmark the scalability and query execution time of Neo4j for hierarchical competency mapping. - Prove the algorithmic efficiency of dynamic Knowledge Tracing in reducing the total number of required learning modules for a user. c. Research Scope & Methodology In scope:  Neo4j graph construction; Graph-traversal algorithms; Polyglot database architecture; Recommendation benchmarking.  Out of scope:  Generative AI for content creation; Video streaming infrastructure; LMS SCORM compliance. Methodology: - Experiment 1 (RQ1 - Accuracy):  Create a synthetic dataset of 500 users with varying skill gaps. Ask subject matter experts to annotate the "correct" top 5 learning modules for 50 sample profiles. Compare the Graph Algorithm output vs Baseline output against this golden set. - Experiment 2 (RQ2 - Graph Latency):  Populate Neo4j with synthetic ontologies of increasing size (1k, 5k, 10k nodes). Execute the shortest-path learning recommendation query 1,000 times per size and record latency (Mean, P95). - Experiment 3 (RQ3 - Pathway Efficiency):  Simulate 100 learners failing random modules. Calculate the total number of remedial modules assigned by the adaptive graph algorithm vs a static curriculum approach. d. Expected Scientific Contribution - Empirical evaluation of Knowledge Graph traversal algorithms for adaptive learning recommendations. - Scalability benchmarks for applying Neo4j to highly relational educational ontologies. - A functional software architecture blueprint combining relational and graph databases for intelligent HR tech applications. Other Comments: SE Specialization - Data-Intensive & Algorithmic Systems:  The primary academic deliverables are the polyglot database architecture (Neo4j + PostgreSQL) and the graph-traversal recommendation algorithm. Content & Demo Constraints:  Creating actual educational content (recording videos, building SCORM packages, writing detailed course syllabi) is strictly out of scope. The evaluation will be conducted using a curated, synthetic dataset of skills and dummy learning modules to mathematically prove the algorithmic correctness and latency of the Knowledge Graph traversal. The system is a proof-of-concept for the recommendation engine, not a fully featured Learning Management System (LMS) intended to immediately replace commercial platforms. 4.
