## Description

Create comparable static and adaptive pathway scenarios for 100 simulated learners, with module failures as described in the registration.

**Input:** Initial learner states, target roles, static curriculum, and reproducible failure scenarios.  
**Outcome:** An RQ3 simulation dataset for evaluating remedial module counts and target-role gap/distance.

## Open Decisions

The following decisions were confirmed on 2026-10-04:

- Create a separate 100-learner RQ3 population from the ontology, using the RQ1 V9 profile-generation mechanism; do not copy learners from the RQ1 500-user dataset. Keep the 40% SE / 30% DATA / 30% AI split.
- Use a fixed 20% module-failure probability, generated from a seed-derived learner/module key. Both pathway methods receive the same potential outcome for the same learner and module. Outcomes are provided for every active module, not only the static route.
- Permit one first attempt per learner/module; do not model retries. The evaluator stops when all observed required skills meet their target or no eligible module remains, and reports unknown required skills separately.
- Successful completion sets each taught skill to `max(currentMastery, TEACHES.outcomeMastery)`; an unknown skill receives the outcome mastery. This is a synthetic transition assumption, not evidence of real learning.
- The static route is fixed before failures are sampled. On failure, it may use one pre-authored eligible fallback for that module, with no dynamic replanning or nested fallback. Route and fallback modules must satisfy entry requirements from the initial state so earlier failures cannot make the fixed choices ineligible.
- Primary gap measure: mean positive shortfall over observed required skills, excluding unknown values. Also report observed target-hit rate, unmet observed skill count/codes, unknown skill count, and uncovered initial gaps. Report assigned and remedial module counts separately; module count alone is not evidence of competency validity.

## Dataset fixture

Generated by `documents/dataset/generate_rq3_scenarios.py` into
`documents/dataset/outputs/rq3_v1/rq3_scenarios_100_v1.json`. The output records
the source workbook hash, seed, all 100 initial learner states, role/module
requirements, fixed static routes and fallbacks, and 5,000 paired potential
learner/module outcomes. The fixture does not contain measured adaptive-pathway
results; those are produced when the application algorithms are evaluated.

Residual role gaps that no eligible module can reduce are retained in the
scenario, rather than silently treated as covered. Synthetic rates and mastery
transitions must be described as simulation assumptions in RQ3 results.

## Acceptance Baseline

Both algorithms can be evaluated against equivalent scenarios; fewer modules alone must not be treated as proof of valid competency coverage.
